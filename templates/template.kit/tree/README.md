## Working on it

```sh
make check      # validate the manifest and payload
make install    # copy it into ~/sqsysroot/.squared/resources, exploded
make dist       # pack it into dist/
```

`install` copies the directory rather than an archive. An exploded cartridge
means the same thing as a packed one, so an edit here is visible to `sqpg` on
the next run with no repack — edit, test, repeat.

Try it against a real project:

```sh
make install
cd ~/sqsysroot/sandbox
sqpg new probe -t template.terminal.cpp -k kit.{{project_name}}
cd probe && make
```

## What to edit first

`cartridge/SQ-INF/manifest.json`. Three fields decide what the kit is:

- **`integration_areas`** — the anchors in a template this kit fills. A kit
  that only contributes files needs `build.make.fragments` and nothing else.
- **`runtime.model`** — `none`, `polled` or `callback`. `none` unless the kit
  wraps something with a main loop.
- **`external`** — what it wraps. Leave `id` empty for a kit that contributes
  only files.

Then put your payload under `cartridge/tree/`. Paths there are relative to the
generated workspace root, not to `tree/`.

## Where the rules are

`make check` runs `sqcart verify`, which checks the container and the
envelope. It does **not** check what squared-pg requires of a kit — the
container format carries that section without interpreting it. Those rules are
in Generator Architecture §2.9.2, and the fields read by nothing are marked
there as reserved, so you can tell which of them currently do anything.
