## Build and run

```sh
make          # build
make run      # build and run
./run.sh      # the same, in one step
```

No CMake, no package manager, no network. A compiler and `make` are the whole
dependency list — which is the point of this template: it is meant to work on
a phone.

## Layout

```text
sq_app/        your code — headers in include/, sources in src/
sq_kit/        kit-provided headers (generator-owned)
mk/            generated build fragments (generator-owned)
Makefile       yours; includes the fragments above
.squared/      how this workspace was generated (generator-owned)
```

## Who owns what

| Path | Owner | On update |
|---|---|---|
| `sq_app/**` | you | never touched |
| `Makefile`, `README.md`, `.gitignore` | you | never touched |
| `sq_lua/**` (with kit.lua) | you | never touched |
| `mk/**`, `sq_kit/**` | generator | rewritten |
| `.squared/**` | generator | rewritten |

Every generated path is recorded in `.squared/metadata.json` with the hash it
had when it was written, so a later update can tell "unchanged since
generation" from "the user edited this" without guessing.

You can delete `.squared/` and keep a working project. You lose only the
ability to update it in place.

## Independence

This workspace does not depend on squared-pg. The generator is not on the
build path, is not referenced by the Makefile, and does not need to be
installed to build, run, test or distribute what it produced.
